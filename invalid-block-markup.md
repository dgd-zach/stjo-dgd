# Invalid block markup: render-time classes in stored content

Generated by hand on 2026-08-20 14:33. Re-check with:

```bash
grep -rnE 'is-layout-|is-content-justification|wp-container-core-' inc/patterns inc/page-content template-parts
```

## The problem

`is-layout-*`, `wp-block-*-is-layout-*`, `is-content-justification-*` and
`wp-container-core-*` are added by WordPress's layout support **at render time**.
A block's `save()` never writes them. Gutenberg validates stored markup against
what `save()` would produce and compares `class` as a set, so any extra class
trips "This block contains unexpected or invalid content".

The front end is unaffected. The risk is in the editor: an editor who clicks
**Attempt recovery** or **Convert to HTML** on the warning bar rewrites or
flattens the block.

Confirmed against this site: post 8 (Our History), which has been through the
editor, contains zero such classes. Its covers are bare
`class="wp-block-cover__inner-container"` and its buttons bare
`class="wp-block-buttons"`. WP 7.0.4 also emits
`wp-block-cover-is-layout-constrained`, not the
`wp-block-cover__inner-container-is-layout-constrained` these files carry, so the
baked-in class is a stale variant as well as a surplus one.

Origin: the `inc/patterns/*` files were generated from **rendered** HTML by the
figma-to-wp pipeline, so they captured render-time output as if it were save
output. Anything built by copying a pattern inherits it.

## Second issue: HTML entities in JSON block attributes

`metadata.name` is a plain-text label. Entities are not decoded there, so
`"name":"Akt&aacute; Lakota Museum CTA"` shows literally in the List View. Use
the real character. This does not invalidate the block, it only mislabels it.

### Leave alone: template parts

| File | Classes |
| --- | --- |
| `template-parts/global/pre-footer.php` | `is-layout-flex`, `is-content-justification-center` |

**Do not strip these.** A template part prints raw HTML; its block comments are
inert and WordPress never runs the layout renderer over it. Verified on the
rendered page: the pre-footer's buttons come out as
`wp-block-buttons is-layout-flex is-content-justification-center` with no
`wp-container-core-*` and no `wp-block-buttons-is-layout-flex`, i.e. WordPress
added nothing. Those two classes are what centres the Donate button. Removing
them would break the layout, and there is no editor to confuse.
